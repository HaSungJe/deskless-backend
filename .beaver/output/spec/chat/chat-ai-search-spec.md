# AI 대화형 업체 검색

## 한눈에

- **무엇을** 로그인한 이용자가 대화로 여행지 · 숙소를 찾는다. AI(Gemini)가 웹 검색으로 지역 · 관광지를 알아보고, 업체 정보 벡터 검색과 편의시설 · 객실 · 거리 조건으로 업체를 골라 최대 3곳을 카드로 추천하며, 답은 글자 단위로 흘려보낸다. 질문은 하루(한국 시각 자정 초기화) 5회 · 100자까지.
- **왜** 지금은 지도 반경 · 필터로만 찾을 수 있어 "온천 가고 싶은데 반려동물도 같이", "제주 여행지 두 곳 사이 · PC · 방 2개" 같은 요구를 풀 수 없다. ① 편의시설 · ② 전국 테스트 업체가 그 재료다.
- **범위 밖** 하루 한도를 넘는 유료 질문, 대화창 여러 개 · 대화창 전환, 관리자가 대화를 보는 화면, 예약까지 대화로 하기, 음성 · 이미지 입력, 대화 내보내기, 비로그인 이용.

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 대화 보기 | 내 대화 이력 · 오늘 남은 질문 수를 본다 | 1건 |
| 2. 남은 질문 수 | 오늘 남은 질문 수 · 초기화 시각 · 답하는 중인지 본다 | 1건 + 계산 4건 |
| 3. 메시지 보내기 | 질문을 보내면 AI 답이 글자 단위로 오고 업체 카드가 붙는다 | 4건 |
| 4. 대화 초기화 | 내 대화 이력을 바로 모두 지운다 | 1건 |
| 5. 업체 정보 벡터 갱신 | 바뀐 업체만 검색용 벡터를 다시 만든다 | 0건 |
| 6. 지난 대화 지우기 | 7일 지난 대화를 지운다 | 0건 |

## 1. 대화 보기 — `GET /api/v1/user-service/chat`

**동작 흐름**

1. **이력 읽기** — 이 이용자의 대화(질문 + 답)를 오래된 순으로 읽는다(7일 안 — 업체 카드 포함).
2. **횟수 읽기** — 오늘(한국 날짜) 답을 받은 질문 수로 남은 질문 수를 셈한다(진입점 2와 같은 계산).

**입력** — 없음(로그인 이용자)

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 대화한 이용자가 본다 | 200 `{messages: [{role, content, stores, created_at}], quota}` — 질문 한 건이 `USER` · `AI` 두 메시지로 펼쳐진다, `quota` 는 진입점 2와 같은 모양 | ✓ 정상 |
| 대화한 적이 없거나 초기화했다 | 200 `messages` 빈 배열 · 오늘 남은 질문 수 | — (위 정상과 같은 읽기) |
| 로그인하지 않았다 · 다른 그룹 토큰 | 401 | — (가드 공통) |

## 2. 남은 질문 수 — `GET /api/v1/user-service/chat/quota`

**동작 흐름**

1. **오늘 정하기** — 지금 시각의 한국 날짜(`yyyy-MM-dd`)와 초기화 시각(다음 날 00:00)을 정한다.
2. **오늘 질문 수 읽기** — 이용자의 횟수 한 줄(`날짜:횟수` — 답을 받을 때마다 1씩 오른다, 초기화해도 남는다)을 읽는다. 저장된 날짜가 오늘이 아니면 0회다.
3. **남은 수** — 하루 한도에서 뺀 남은 수 · 초기화 시각(다음 날 00:00) · 답하는 중인지를 돌려준다.

**입력** — 없음(로그인 이용자)

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 이용자가 본다 | 200 `{daily_limit, used_count, remaining_count, resets_at, is_answering}` | ✓ 정상 |
| 로그인하지 않았다 | 401 | — (가드 공통) |

**계산 규칙 — 오늘 남은 질문 수**

입력: 지금 시각 · 저장된 한 줄(날짜 · 횟수). 출력: 오늘 날짜(한국 `yyyy-MM-dd`) · 오늘 쓴 수 · 남은 수 · 초기화 시각.
검증: 한국 시각 날짜로 하루를 나누고(서버가 UTC 여도), 이용자의 줄이 없거나 저장된 날짜가 오늘이 아니면 오늘 쓴 수는 0, 남은 수는 하루 한도(`.env` `CHAT_DAILY_LIMIT` — 기본 5, 아래 표는 5 기준)에서 오늘 쓴 수를 뺀 값(0 아래로 가지 않는다), 초기화는 다음 날 한국 00:00 이다.

| 확인하는 것 / 상황 | 결과 |
|---|---|
| 오늘 날짜로 두 번이 저장돼 있다 | 남은 3회, 초기화는 다음 날 00:00(한국) |
| 오늘 날짜로 다섯 번이 저장돼 있다 | 남은 0회 — 질문하면 막힌다 |
| 한국 시각 밤 11시 59분에 묻는다 | 그날 날짜로 세고, 초기화는 1분 뒤 |
| 어제 날짜로 다섯 번이 저장돼 있는데 한국 시각 자정(서버 UTC 로는 전날 오후 3시)이 지났다 | 저장된 날짜가 오늘이 아니라 0회로 보고 다시 5회 |

## 3. 메시지 보내기 — `POST /api/v1/user-service/chat/message`

응답은 SSE 스트림(내부 HTTP 스트리밍 — 게이트웨이가 user-service 의 스트림을 그대로 흘린다). 시작 전 실패는 일반 HTTP 상태 + 실패 본문, 시작 뒤 실패는 `failed` 이벤트.

**동작 흐름**

1. **답하는 중 잠금** — 이 이용자의 다른 질문이 답하는 중이면 막고, 아니면 잠근다(끝나면 푼다).
   - 답하는 중이면 → 409
2. **횟수 확인** — 오늘 남은 질문이 없으면 막는다(잠금을 풀고).
   - 0회면 → 429(초기화 시각)
3. **요청 읽기** — 최근 대화 이력을 붙여 AI 가 웹 검색으로 여행 관련인지, 찾을 지역 · 편의시설 · 객실 조건 · 검색 문장을 뽑는다.
   - 여행지 · 숙소 찾기와 무관한 말이면 → 업체를 찾지 않고 여행 이야기로 돌리는 짧은 답만
4. **업체 찾기** — 검색 문장 벡터와 조건(지역 거리 · 편의시설 · 객실 · 영업 중 · 이력에서 이미 추천한 업체 제외)으로 최대 3곳을 골라 카드로 보낸다.
   - 지역 추천 · 되묻기라 업체가 필요 없으면 → 카드 없이 답만
5. **답 쓰기** — 카드 업체 · 대화 이력으로 AI 답을 글자 조각으로 흘려보낸다.
6. **이력 저장** — user_id · 질문 + 답(카드) · 시각을 한 건으로 이력에 더하고, user_id 로 횟수 한 줄을 찾아 바꾼 뒤(없으면 `오늘:1` 등록 · 어제 날짜면 `오늘:1` 로 · 오늘 날짜면 +1) 잠금을 푼다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `content` | ✓ | 질문(1 ~ 100자) |

**스트림 이벤트** — `progress {phase}`(`SEARCHING_WEB` · `SEARCHING_STORES` · `ANSWERING`) → `stores {list}`(카드 0 ~ 3) → `delta {text}`(여러 번) → `done {message, quota}` · 실패면 `failed {status_code, message, validation_errors}`

**업체 카드** — `store_id` · `store_name` · `address` · `latitude` · `longitude` · `image_url`(대표 사진, 없으면 null) · `facilities`(있는 편의시설 · 객실 항목 `{key, name, group}` — 업체 편의시설 7개 중 있는 것 + 그 업체 객실 그룹에 있는 항목: PC · 방 2개 이상 …)

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 여행 · 숙소 질문을 보낸다 | 200 스트림 — `progress` → `stores`(최대 3곳) → `delta` … → `done {message, quota}`. 이력에 한 건이 쌓이고 오늘 횟수가 1 오르며 잠금이 풀린다. 여행과 무관한 말이면 카드 없이 돌리는 답(역시 1회) | ✓ 정상 |
| 오늘 5회를 다 썼거나 다른 질문에 답하는 중이다 | 다 씀 429 `{message, validation_errors: null, resets_at}` · 답하는 중 409 `{message, validation_errors: null}`, AI · 업체 검색 없음 | ✓ 실패 |
| 빈 질문 · 100자 초과 | 400, 필드별 오류(`content`) | ✓ 검증 실패 |
| 답을 쓰는 중 AI 가 실패한다 | 스트림에 `failed {status_code: 503, …}` — 이력에 저장하지 않고 횟수도 오르지 않으며, 잠금은 풀린다 | ✓ 실패 |
| 조건에 맞는 업체가 없다 | 카드 없이 조건을 넓혀 보라는 답 | — (AI 문장 — 결과가 정해지지 않는다) |
| 이용자가 중간에 연결을 끊는다 | AI 요청을 멈추고 저장하지 않는다(횟수 그대로) · 잠금을 푼다 | — (전송 계층 — 게이트웨이 인프라) |
| 로그인하지 않았다 | 401 | — (가드 공통) |

## 4. 대화 초기화 — `DELETE /api/v1/user-service/chat`

**동작 흐름**

1. **이력 지우기** — 이 이용자의 대화 이력을 7일을 기다리지 않고 바로 모두 지운다(지우기용 목록에서도 뺀다).
2. **횟수는 남긴다** — 횟수 한 줄은 지우지 않는다(초기화로 하루 한도를 넘기지 않게).

**입력** — 없음(로그인 이용자)

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 대화 중에 초기화한다 | SSE `done`(data 없음) — 이후 대화 보기는 빈 이력, 오늘 남은 질문 수는 그대로 | ✓ 정상 |
| 로그인하지 않았다 | 401 | — (가드 공통) |

## 5. 업체 정보 벡터 갱신 — `CRON scheduler store-embedding (1시간마다)`

**동작 흐름**

1. **검색용 글 만들기** — 영업 중인 업체마다 이름 · 주소 · 소개 · 편의시설 · 객실(이름 · 설명 · 방 수 · PC) · 판매 상품을 한 글로 만든다.
2. **바뀐 업체 고르기** — 저장된 내용 해시와 다르거나 벡터가 없는 업체만 고른다.
   - 없으면 → 끝
3. **벡터 만들기** — 고른 업체의 글을 Gemini 임베딩으로 바꿔 저장한다.
   - AI 가 실패하면 → 그 회차는 건너뛰고 다음 회차에 다시

**입력** — 없음(1시간마다 1회 — 매시 30분, 여러 대여도 한 대만 — JobLockService)

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 소개 · 편의시설 · 객실이 바뀌었다 | 다음 회차에 그 업체만 다시 벡터를 만든다 | — (scheduler crontab spec 은 두지 않는다 — 조회 쿼리는 repository Smoke) |
| 바뀐 업체가 없다 | AI 호출 없음 | — (위와 같음) |

---

## 6. 지난 대화 지우기 — `CRON scheduler chat-purge (1시간마다)`

**동작 흐름**

1. **이용자 훑기** — 이력이 있는 이용자 목록에서 이용자마다 7일(24 × 7시간) 지난 대화를 지운다.
2. **빈 이용자 빼기** — 대화가 하나도 남지 않은 이용자는 목록에서 뺀다.

**입력** — 없음(1시간마다 — 매시 정각 · 한 대만)

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 7일 지난 대화가 있다 | 그 대화만 지운다(최근 대화는 남는다 — 오늘 횟수에는 영향 없음) | — (scheduler crontab spec 은 두지 않는다) |

## 데이터 변화

| 대상 | 무엇이 바뀌나 |
|---|---|
| `t_store_embedding`(신규) | 업체마다 1행 — 검색용 글 · 내용 해시 · 벡터(`vector(768)`) · 모델 이름. pgvector 확장(`CREATE EXTENSION vector`)을 마이그레이션이 켠다. 지워진 업체 행은 남아도 검색이 업체 상태로 거른다 |
| Redis 대화 이력 | `chat-turns:<user_id>`(질문 + 답 한 건씩 — `{turn_id, user_id, question, answer, stores, asked_at, answered_at}`, 점수는 물은 시각, 7일 뒤 지움 · 초기화하면 바로 전부 지움) · `chat-users`(이력이 있는 이용자 — 지우기용) |
| Redis 횟수 · 잠금 | `chat-usage:<user_id>`(이용자마다 한 줄 — 값 `yyyy-MM-dd:횟수`, 예: `2026-11-25:3`. 날짜가 바뀐 뒤 처음 쓸 때 오늘 날짜 · 1 로 바뀐다, 초기화해도 남는다, 7일 동안 안 쓰면 만료) · `chat-busy:<user_id>`(답하는 중 — 끝나면 풀고, 서버가 죽어도 3분 뒤 만료). 대화창 · 벌점 · 정지 키는 두지 않는다 |
| `.env` | `GEMINI_API_KEY`(user-service · scheduler) · `GEMINI_CHAT_MODEL` · `GEMINI_EMBEDDING_MODEL` · `CHAT_DAILY_LIMIT`(5) |

## 결정한 것

- [x] AI 는 Gemini, 웹 검색은 Google 검색 그라운딩, 업체 정보는 pgvector 벡터 DB(Redis 스냅샷은 쓰지 않는다). 프론트는 백엔드 API 로 붙는다(사용자 결정 2026-11-24).
- [x] 로그인 이용자만, **하루 5회**(한국 시각 자정 00:00 초기화 — 횟수는 `.env` `CHAT_DAILY_LIMIT` 로 정한다, 비면 5) · **질문 100자 이내**. 남은 질문 수 · 초기화 시각을 따로 보는 API 를 둔다(사용자 결정 2026-11-25).
- [x] **대화창 개념은 없다** — 대화 이력은 이용자마다 하나(`user_id` · 질문 + 답 · 시각을 함께 저장, Redis). AI 는 그 이용자의 최근 이력을 참고하고, 다른 PC 에서도 같은 이력을 본다(사용자 결정 2026-11-25).
- [x] **대화 초기화 = 그 이용자의 이력을 7일 기다리지 않고 바로 모두 지운다**(사용자 결정 2026-11-25). 평소에는 7일 지난 대화를 scheduler 가 주기적으로 지운다(사용자 결정 2026-11-24). DB 소프트 삭제 규칙은 DB 에만 — Redis 대화는 실제로 지운다.
- [x] 횟수는 **이용자마다 한 줄**(`chat-usage:<user_id>` = `yyyy-MM-dd:횟수` — user_id · 한국 날짜 · 횟수)로 센다. 줄이 없으면 0회와 같다. 답을 저장할 때 user_id 로 줄을 찾아 — 없으면 `오늘:1` 등록, 어제 날짜면 `오늘:1` 로 바꿈, 오늘 날짜면 +1(사용자 결정 2026-11-25). 읽을 때는 줄이 없거나 오늘이 아니면 0회로 본다 — 날짜를 바꾸는 별도 작업은 없다. 초기화가 이력을 지워도 이 줄은 남아 하루 한도를 넘기지 못한다(사용자 결정 2026-11-25). 답을 다 받은 질문만 센다 — AI 실패 · 끊김은 저장하지 않아 오르지 않는다. 여행과 무관한 말에 대한 안내 답도 1회.
- [x] 잡담 벌점 · 24시간 정지 · 30초 간격은 **없앤다** — Redis 에 벌점 정보를 두지 않는다(사용자 결정 2026-11-25). 대신 한 이용자의 질문은 한 번에 하나만 답한다(답하는 중 잠금 — 동시에 보내 한도를 넘는 것을 막는다).
- [x] 여행지 · 숙소 찾기와 무관한 말에는 업체를 찾지 않고 여행 이야기로 돌리는 짧은 답을 준다(불이익 없음).
- [x] 답은 글자 단위 스트리밍 — **내부 HTTP 스트리밍**(게이트웨이가 user-service 의 SSE 스트림을 그대로 흘린다). 큐를 거치지 않는 세 번째 전달 경로라 "쓰기는 큐" 규칙의 예외로 문서에 적는다(사용자 결정 2026-11-24 — 브라우저 WebSocket 은 헤더 인증을 못 해 지금 소켓 규칙과 맞지 않는다).
- [x] 답 글 + 업체 카드 최대 3곳 — 대표 사진 · 업체명 · 주소 · 위경도 · 있는 편의시설(업체 편의시설 + 객실 항목). "마음에 안 든다" 면 이력에서 이미 추천한 업체를 빼고 다시 3곳(사용자 결정 2026-11-24).
- [x] 대화 초기화는 상태를 바꾸는 쓰기라 지금 큐(SSE) 경로(지우는 동작이라 `DELETE`), 대화 보기 · 남은 질문 수는 동기 조회.
- [x] 업체 정보 벡터 갱신은 1시간마다 1회(사용자 결정 2026-11-25 — 너무 잦지 않게) — 바뀐 업체만 임베딩한다. 업체 정보를 바꾸면 최대 1시간 뒤 AI 검색에 반영되고, 그 사이 새 업체도 조건이 맞으면 벡터 없이 뒤에 나온다(추천 쿼리 `NULLS LAST`). 지난 대화 지우기(매시 정각)와 겹치지 않게 매시 30분에 돈다.
- [x] 프론트 요청서 — 메인 화면의 "가까운 순" 글자를 빼고 AI 검색을 넣는다, 스트림 읽기 · 카드 · 남은 질문 수 · 100자 · 대화 초기화(새 기능마다 요청서 — 고정 규칙).
- [x] deskless 에 알릴 것 — PostgreSQL 에 pgvector 확장(이미지 · 권한), 스트리밍 경로의 앞단 버퍼링 끔 · 읽기 대기 120초, `GEMINI_API_KEY` 를 user-service · scheduler 에만.
