# 문의사항

## 한눈에

- **무엇을** 이용자가 카테고리를 골라 업체나 바로방에 문의를 남기면, 그 업체의 업체 관리자(업체 문의) · 관리자(바로방 문의)가 답변하고, 상세에서 보고 부적절한(스팸 · 도배) 문의는 한 건씩 블라인드한다. 목록은 카테고리 · 상태로 거른다.
- **왜** 지금은 이용자가 업체 · 운영자에게 물어볼 통로가 없다.
- **범위 밖** LLM(Gemini) 자동 답변 · 스팸 거르기(뺐다), 문의 수정 · 삭제, 답변 알림(SMS), 동의 항목 저장(프론트가 등록 전에 체크만 한다).

| 진입점 | 한 줄 요약 | 테스트 |
|---|---|---|
| 1. 업체 이름 검색 | 문의할 업체를 이름으로 찾고 주소 · 위치 · 대표 사진을 본다 | 2건 |
| 2. 문의 카테고리 목록 | 고를 수 있는 카테고리를 정해 둔 순서로 본다 | 1건 |
| 3. 문의 등록 | 카테고리를 골라 업체 또는 바로방에 문의를 접수한다 | 4건 |
| 4. 내 문의 목록 | 내가 쓴 문의를 카테고리 · 상태로 걸러 최신순으로 본다 | 2건 |
| 5. 내 문의 상세 | 내 문의와 답변을 본다 | 1건 |
| 6. 문의 목록 (관리) | 업체 관리자는 내 업체, 관리자는 바로방 문의를 카테고리 · 상태 · 검색어로 걸러 본다 | 3건 |
| 7. 문의 상세 (관리) | 범위 안 문의의 작성자 · 내용 · 답변을 본다 | 1건 |
| 8. 문의 답변 | 답변을 달거나 고치고 답변완료로 바꾼다 | 5건 |
| 9. 문의 블라인드 | 상세에서 본 문의 한 건을 블라인드한다 | 2건 |
| 10. 문의 블라인드 해제 | 블라인드된 문의 한 건을 원래 상태로 되돌린다 | 3건 |

## 1. 업체 이름 검색 — `GET /api/v1/user-service/discovery/store-search`

**동작 흐름**

1. **이름 검색** — 상호명에 검색어가 들어간 업체를 찾는다(영업 중 · 영업중지만, 탈퇴 · 지운 업체는 빠진다).
2. **목록 반환** — 상호명 순으로 최대 20건을 주소 · 위경도(지도에서 위치 확인) · 대표 사진 1장과 함께 돌려준다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `keyword` | ✓ | 검색어(50자까지) — 상호명 부분 일치. 로그인 없이 쓴다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 검색어에 맞는 업체가 있다 | 200, `{list: [{store_id, store_name, address, latitude, longitude, image_url}]}` — 최대 20건, 대표 사진은 업체 사진 첫 장의 공개 주소(사진이 없으면 `image_url` null) | ✓ 정상 |
| 맞는 업체가 없다 | 200, 빈 목록 | — (같은 조회) |
| 검색어가 비었거나 50자를 넘는다 | 400 | ✓ 검증 실패 |

## 2. 문의 카테고리 목록 — `GET /api/v1/user-service/inquiry/category`

**동작 흐름**

1. **카테고리 읽기** — 기본 데이터로 넣어 둔 카테고리를 정해 둔 순서대로 읽는다.
2. **목록 반환** — ID 와 이름을 돌려준다.

**입력**

없음 — 로그인 없이 쓴다. 이용자 문의 등록 · 내 문의 목록 거르기 · 관리 목록 거르기 화면이 같이 쓴다.

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 카테고리를 본다 | 200, `{list: [{inquiry_category_id, inquiry_category_name}]}` — 정렬 순서대로(예약 · 결제/환불 · 객실/시설 · 출입/QR · 회원/계정 · 입점 · 기타) | ✓ 정상 |

## 3. 문의 등록 — `POST /api/v1/user-service/inquiry`

**동작 흐름**

1. **대상 확인** — 업체를 골랐으면 그 업체가 영업 중이거나 영업중지인지 확인한다.
   - 탈퇴 · 지운 · 없는 업체면 → 404 `업체를 찾을 수 없습니다.`
   - 업체를 고르지 않았으면 → 바로방 문의로 받는다
2. **문의 저장** — 작성한 이용자 · 대상 업체 · 카테고리 · 제목 · 내용을 접수 상태로 저장한다.
3. **ID 반환** — 새 문의 ID 를 돌려준다.

동의 항목(개인정보 수집 · 이용 동의 등)은 프론트가 등록 버튼 전에 체크하게 한다 — 서버로 보내지 않고 저장하지 않는다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `store_id` | | 문의할 업체(32자 hex) — 없으면 바로방 문의 |
| `inquiry_category_id` | ✓ | 카테고리 — `RESERVATION` · `PAYMENT` · `ROOM` · `DOOR` · `ACCOUNT` · `STORE_APPLICATION` · `ETC` |
| `title` | ✓ | 제목(100자까지) |
| `content` | ✓ | 내용(2000자까지) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 · 카테고리를 골라 문의한다 | SSE `done` `{inquiry_id}` — 그 업체 · 카테고리 · 접수 상태로 저장 | ✓ 정상 |
| 업체를 고르지 않고 문의한다 | `done` `{inquiry_id}` — 업체 없이(바로방) 고른 카테고리로 저장, 업체를 찾지 않는다 | ✓ 정상 |
| 탈퇴했거나 없는 업체를 고른다 | `failed` 404 `업체를 찾을 수 없습니다.`, 저장 없음 | ✓ 실패 |
| 카테고리를 고르지 않았거나 허용값 밖이다 · 제목이 비었거나 100자를 넘는다 · 업체 ID 형식이 틀리다 | 400, 필드별 오류 | ✓ 검증 실패 |
| 로그인하지 않았다 | 401 | — (가드 공통) |

## 4. 내 문의 목록 — `GET /api/v1/user-service/inquiry`

**동작 흐름**

1. **개수 세기** — 내가 쓴 문의 중 고른 카테고리 · 상태(둘 다 선택 — 안 고르면 전체)에 맞는 개수를 센다.
2. **목록 반환** — 같은 조건으로 최신순 그 페이지를 돌려준다(블라인드된 문의도 블라인드 상태로 나온다).

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `page`, `size` | | 페이지(공통 기본값) |
| `inquiry_category_id` | | 카테고리 거르기 — 없으면 전체 |
| `inquiry_state_id` | | 상태 거르기 — 없으면 전체, `RECEIVED` 접수 · `ANSWERED` 답변완료 · `BLIND` 블라인드 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 카테고리 · 상태를 골라 본다 | 200, `{list: [{inquiry_id, store_id, store_name, inquiry_category_id, inquiry_category_name, title, inquiry_state_id, inquiry_state_name, answered_at, created_at}], pagination}` — 개수와 목록이 같은 조건(내 문의 + 카테고리 + 상태) | ✓ 정상 |
| 아무것도 고르지 않고 본다(전체) | 200, 내 문의 전부 — 바로방 문의는 `store_id` · `store_name` 이 null | — (같은 조회, 조건만 빠진다) |
| 카테고리 · 상태 값이 허용값 밖이다 | 400 | ✓ 검증 실패 |

## 6. 문의 목록 (업체 관리자 · 관리자) — `GET /api/v1/admin-service/inquiry/mine · GET /api/v1/admin-service/inquiry`

**동작 흐름**

1. **범위 정하기** — 업체 관리자(`/mine`)는 소속 업체의 문의, 관리자는 업체 대상이 아닌(바로방) 문의로 범위를 정한다.
   - 업체 관리자의 업체가 탈퇴 · 삭제됐으면 → 404 `소속 업체를 찾을 수 없습니다.`(다른 매니저 기능과 같은 문구)
2. **개수 세기** — 범위 안에서 카테고리 · 상태(선택 — 안 고르면 전체) · 검색어(제목 · 내용)에 맞는 개수를 센다.
3. **목록 반환** — 같은 조건으로 최신순 그 페이지를 돌려준다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `page`, `size` | | 페이지(공통 기본값) |
| `inquiry_category_id` | | 카테고리 거르기 — 없으면 전체 |
| `inquiry_state_id` | | 상태 거르기 — 없으면 전체, `RECEIVED` 접수 · `ANSWERED` 답변완료 · `BLIND` 블라인드 |
| `keyword` | | 검색어(100자까지) — 제목 · 내용 부분 일치 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 업체 관리자가 카테고리 · 상태 · 검색어를 골라 본다 | 200, `{list: [{inquiry_id, user_id, user_nickname, inquiry_category_id, inquiry_category_name, title, inquiry_state_id, inquiry_state_name, answered_at, created_at}], pagination}` — 소속 업체 문의 중 조건에 맞는 것만 | ✓ 정상 |
| 관리자가 본다 | 200, 같은 모양 — 업체 대상이 아닌 문의만 | ✓ 정상 |
| 업체 관리자의 업체가 탈퇴했다 | 404, 목록을 읽지 않는다 | ✓ 실패 |
| 카테고리 · 상태 값이 허용값 밖이다 | 400 | — (내 문의 목록과 같은 검증 규칙 — DTO 데코레이터) |
| 매니저 토큰으로 관리자 경로를 부른다(또는 그 반대) | 401 | — (가드 공통) |

## 7. 문의 상세 (업체 관리자 · 관리자) — `GET /api/v1/admin-service/inquiry/mine/:inquiry_id · GET /api/v1/admin-service/inquiry/:inquiry_id`

2. **상세 반환** — 작성자 · 카테고리 · 내용 · 답변 · 블라인드 정보를 돌려준다.

**입력**

|---|---|---|

**결과**

| 범위 안 문의를 본다 | 200, `{inquiry_id, user_id, user_nickname, store_id, inquiry_category_id, inquiry_category_name, title, content, inquiry_state_id, inquiry_state_name, answer_content, answer_user_name, answered_at, blinded_at, created_at}` — 없는 값은 null | — (조회 위임) |

## 8. 문의 답변 — `PUT /api/v1/admin-service/inquiry/mine/:inquiry_id/answer · PUT /api/v1/admin-service/inquiry/:inquiry_id/answer`

**동작 흐름**

1. **범위 확인** — 문의가 내 범위인지 확인한다(상세와 같은 규칙).
   - 아니면 → 404 `문의를 찾을 수 없습니다.`
2. **블라인드 확인** — 블라인드된 문의는 답변 · 수정할 수 없다.
   - 블라인드면 → 400 `블라인드된 문의에는 답변할 수 없습니다.`
3. **답변 저장** — 답변 내용 · 답변한 계정 · 시각을 적고 답변완료로 바꾼다(이미 답변이 있으면 고쳐 쓴다).
   - 그사이 블라인드됐으면 → 같은 400 으로 되돌린다
4. **완료** — 돌려줄 값 없이 끝난다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `inquiry_id` | ✓ | 문의 ID(32자 hex) |
| `answer_content` | ✓ | 답변(2000자까지) — 통째로 바꾼다 |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 접수 문의에 답한다 | SSE `done`(data 없음) — 답변완료 · 답변 내용 · 답변 계정 · 시각 저장 | ✓ 정상 |
| 답변완료 문의의 답변을 고친다 | `done` — 답변 내용 · 계정 · 시각을 새로 덮어쓴다 | — (위 정상과 같은 쓰기) |
| 블라인드된 문의에 답한다 | `failed` 400, 쓰기 없음 | ✓ 실패 |
| 확인과 저장 사이에 다른 사람이 블라인드했다 | `failed` 400 — 저장이 0행이라 되돌린다 | ✓ 실패 |
| 다른 업체 문의에 답한다 | `failed` 404, 쓰기 없음 | ✓ 실패 |
| 답변이 비었거나 2000자를 넘는다 | 400 | ✓ 검증 실패 |

## 9. 문의 블라인드 — `PATCH /api/v1/admin-service/inquiry/mine/:inquiry_id/blind · PATCH /api/v1/admin-service/inquiry/:inquiry_id/blind`

업체 관리자 · 관리자가 문의 상세에서 내용을 보고 부적절하면(스팸 · 도배) 그 한 건을 블라인드한다.

**동작 흐름**

1. **범위 확인** — 문의가 내 범위인지 확인한다(상세와 같은 규칙).
   - 아니면 → 404 `문의를 찾을 수 없습니다.`
2. **상태 확인** — 이미 블라인드된 문의는 다시 블라인드하지 않는다.
   - 블라인드면 → 400 `이미 블라인드된 문의입니다.`
3. **블라인드** — 블라인드로 바꾸고 처리한 계정 · 시각을 적는다(답변은 그대로 둔다).
   - 그사이 다른 사람이 블라인드했으면 → 같은 400 으로 되돌린다
4. **완료** — 돌려줄 값 없이 끝난다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `inquiry_id` | ✓ | 문의 ID(32자 hex) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 접수 · 답변완료 문의를 블라인드한다 | SSE `done`(data 없음) — 블라인드 · 처리 계정 · 시각 저장, 답변 칸은 그대로 | ✓ 정상 |
| 이미 블라인드된 문의를 블라인드한다 | `failed` 400 `이미 블라인드된 문의입니다.`, 쓰기 없음 | ✓ 실패 |
| 확인과 저장 사이에 다른 사람이 블라인드했다 | `failed` 400 — 저장이 0행이라 되돌린다 | — (답변의 같은 경합과 같은 상태 조건 쓰기) |
| 다른 업체 문의를 블라인드하거나, 관리자가 업체 문의를 블라인드한다 | `failed` 404, 쓰기 없음 | — (답변과 같은 범위 확인 — 정상 케이스가 조건의 범위를 단언) |
| 문의 ID 형식이 틀리다 | 400 | — (상세 · 답변과 같은 path 검증) |

## 10. 문의 블라인드 해제 — `PATCH /api/v1/admin-service/inquiry/mine/:inquiry_id/unblind · PATCH /api/v1/admin-service/inquiry/:inquiry_id/unblind`

잘못 블라인드한 문의를 상세에서 한 건씩 되돌린다.

**동작 흐름**

1. **범위 확인** — 문의가 내 범위인지 확인한다(상세와 같은 규칙).
   - 아니면 → 404 `문의를 찾을 수 없습니다.`
2. **상태 확인** — 블라인드된 문의만 푼다.
   - 블라인드가 아니면 → 400 `블라인드된 문의가 아닙니다.`
3. **해제** — 답변이 있으면 답변완료, 없으면 접수로 되돌리고 블라인드 기록(계정 · 시각)을 지운다.
   - 그사이 다른 사람이 풀었으면 → 같은 400 으로 되돌린다
4. **완료** — 돌려줄 값 없이 끝난다.

**입력**

| 필드 | 필수 | 설명 |
|---|---|---|
| `inquiry_id` | ✓ | 문의 ID(32자 hex) |

**결과**

| 상황 | 응답 | 테스트 |
|---|---|---|
| 답변이 있는 블라인드 문의를 푼다 | SSE `done`(data 없음) — 답변완료, 블라인드 칸 비움 | ✓ 정상 |
| 답변이 없는 블라인드 문의를 푼다 | `done` — 접수, 블라인드 칸 비움 | ✓ 정상 |
| 블라인드가 아닌 문의를 푼다 | `failed` 400 `블라인드된 문의가 아닙니다.`, 쓰기 없음 | ✓ 실패 |
| 다른 업체 문의를 풀거나, 관리자가 업체 문의를 푼다 | `failed` 404, 쓰기 없음 | — (답변과 같은 범위 확인 — 정상 케이스가 조건의 범위를 단언) |
| 확인과 저장 사이에 다른 사람이 풀었다 | `failed` 400 — 저장이 0행이라 되돌린다 | — (블라인드의 같은 경합과 같은 상태 조건 쓰기) |

- [x] 업체 관리자의 소속 업체는 예약 현황과 같은 조회(탈퇴 · 지운 업체 제외)를 inquiry repository 에 둔다. 근거: reservation.repository.ts:85 `findManagerStore`
