# 프로젝트 이름 바꿈(roomless → Deskless · 바로방) — 프론트 수정 요청 (2026-11-22)

- 백엔드: spec `.beaver/output/spec/platform/project-rename-spec.md` · 커밋 2026.11.22
- 반영 순서: 상관없음 — API 주소 · 요청 · 응답 · 실패 모양은 그대로다

## 바뀐 이유
roomless 는 "방이 없다" 로 읽혀 서비스와 뜻이 맞지 않았다. 영어 이름은 **Deskless**(프런트 데스크 없는 무인 숙소), 한글 이름은 **바로방**(예약하고 바로 들어가는 방) — 한 브랜드의 영어 · 한글 이름이다.

## 영향 화면
- 화면마다 보이는 서비스 이름(머리줄 · 로고 · 페이지 제목) — 세 영역 모두
- U · M · A 의 SMS 를 받는 흐름(인증번호 · 아이디 찾기 · 비밀번호 초기화 · 입점 승인 · 업체 관리자 등록 · 업체 취소 · 호실 이동 · 이용 중 취소 요청 · QR 확인 링크) — 문자 머리말만 바뀐다
- 테스트 데이터로 보는 화면(지도 · 업체 상세 · 업체 관리자 로그인) — 업체 이름 · 사진 간판

## API 변경
| 구분 | 메서드 · 주소 | 방식 | 바뀐 점 |
|---|---|---|---|
| 변경 | (API 없음 — 서버가 보내는 SMS) | — | 머리말 `[roomless]` → `[바로방]`. 예: `[바로방] 인증번호 [123456] — 5분 안에 입력해주세요.` |
| 변경 | Swagger `/swagger` | — | 기본 제목 `Roomless API` → `Deskless API` |
| 변경 | 테스트 데이터(`SEED_SAMPLE_DATA=1`) | — | 업체 10곳 이름 `룸리스 강남역점` … → `바로방 강남역점` …, 업체 사진 간판 글자 `DESKLESS`. 업체 ID · 업체코드 · 로그인 계정은 그대로([2026-11-13-sample-data.md](2026-11-13-sample-data.md)) |

API 주소 · 요청 · 응답 · 실패 · 동기/큐는 하나도 바뀌지 않았다. DTO 예시값(`@ApiProperty` example)의 업체 이름만 `바로방 강남점` 으로 바뀌었다.

## 화면 구성과 쓰는 API 의 변경
- 화면의 서비스 이름을 새 이름으로 바꾼다 — 한글 자리는 `바로방`, 영어 자리(로고 · 도메인 · 코드 이름)는 `Deskless`. 어느 쪽을 어디에 쓸지는 프론트가 정한다.
- 화면 설계 원본(`design/user.html` · `manager.html` · `admin.html`)은 글자만 바꿨다(한글 `룸리스` → `바로방`, 영어 `roomless` → `deskless`). 게시된 아티팩트 3개는 다시 게시하지 않아 옛 이름이 보인다 — 원본 HTML 을 기준으로 본다.
- 백엔드 저장소 이름이 `roomless-backend` → `deskless-backend` 로 바뀌었다(GitHub 은 옛 주소를 새 주소로 넘겨 준다). 프론트 저장소 이름은 프론트가 정한다.
- 로컬 개발 환경을 다시 띄우면 DB 가 비어 새로 시작한다(테스트 데이터는 시드가 다시 넣는다) — 전에 만든 테스트 계정 · 예약은 없어진다.
