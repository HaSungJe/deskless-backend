## 1. 비즈니스 로직 — 진입점별 코드

### 1-1. 테스트 데이터 넣기 — `SAMPLE_STORES` (sample-seed.data.ts)

만드는 함수(`buildSampleStores` 등 — sample-seed.targets.ts)는 모두 `SAMPLE_STORES` 를 돌며 `index + 1` 을 고정 ID 번호로 쓴다. 그래서 바꾸는 것은 배열 하나다. **전국 업체는 끝에만 더한다** — 순서를 바꾸거나 사이에 끼우면 이미 시드가 들어간 개발 DB 의 고정 ID 가 다른 업체를 가리킨다(PK 로 건너뛰므로 고쳐지지도 않는다).

### 1-2. 샘플 사진 그리기 — `GROUP_COUNTS` · 색 (scripts/sample-images.mjs)

## 3. 데이터 규칙 — 규약만으로 예측할 수 없는 부분

### 3-1. 전국 업체 파일 — `libs/database/src/seeder/sample-seed.region.data.ts`

- **왜 새 파일인가** — 61곳이 1,200줄을 넘는다. 지금 파일(431줄)에 넣으면 문의 본보기와 섞여 읽기 어렵다.
- **왜 판매 종류 · 상세정보를 다시 적나** — 이 파일이 `sample-seed.data.ts` 의 값(`DETAIL_BASIC` · `PLANS_ALL`)을 가져오면 서로 값을 가져오는 순환 import 가 된다. 그러면 ESM 에서 먼저 읽힌 쪽이 아직 정의되지 않은 값을 만나 부팅 시드가 깨진다. 그래서 이 파일은 `sample-seed.data.ts` 에서 **타입만**(`import type` — 실행 때 지워진다) 가져오고, 판매 종류 3줄과 상세정보 값은 그룹 본보기 안에 다시 적는다.
- **요금은 등급표** — 업체마다 숫자를 새로 짓지 않고 도심 · 휴양 · 섬 세 등급 × 그룹 종류 표(`PRICE`)에서 가져온다. 판매하지 않는 종류는 그 업체에서 `null` 로 덮는다(아래 3-3 규칙). `satisfies` 로 묶어 둬서 표에 없는 조합(예: `PRICE.CITY.OCEAN`)을 쓰면 typecheck 가 실패한다.

### 3-3. 표의 빈 칸 · 공통 규칙

| 항목 | 규칙 | 이유 |
|---|---|---|
| 운영 빈 칸 | `is_always_open: 1` · `hours: []` · `breaks: []` · `PLANS_ALL` | 대부분 24시간 · 전 상품(서울 샘플과 같은 섞임 — 영업시간 업체는 5곳만) |
| 영업시간 업체 | `is_always_open: 0` · `hours: sampleHours(시작, 마감[, 휴무 요일])` · 연박 없음이면 `PLANS_NO_LONG` | 휴무가 아닌 날은 두 시각 세트(CHK_StoreHour_OpenCloseTime) — `sampleHours` 가 그렇게 만든다 |
| 판매하지 않는 종류의 그룹 요금 | 그 종류만 `null` 로 덮는다 — 연박 없음 `{...PRICE.X.Y, LONG: null}`, 시간 이용만 `{…, NIGHT: null, LONG: null}` | 업체 상품 설정이 꺼진 종류를 그룹에서 팔지 않게(`is_used` 0 · 요금 0) |
| `usage_hours` | 제주 8곳 4 · 세종 2 · 나머지 3 | 여행지는 시간 이용도 길게 |
| `maintenance_minutes` | 패밀리 · 스위트 그룹이 있으면 30 · 세종 10 · 나머지 0 | 넓은 객실은 정비가 길다 |
| `address_detail` | 모두 `null` | 건물 전체를 쓰는 숙소(서울 샘플은 빌딩 층) |
| 좌표 | 소수 넷째 자리까지 | 지도에서 동네가 맞으면 된다 — 실제 건물과 맞추지 않는다 |

## 테스트

spec 의 "결과" 표에 ✓ 행이 없고 "계산 규칙" 도 없어 테스트로 옮길 것은 0건이다(라이브러리 시드 · 스크립트는 spec 을 두지 않는다 — AGENTS.md Testing). 대신 build 가 일회성 점검 스크립트(scratchpad)로 확인한다 — `nest build user-service` 결과(`dist/apps/user-service/libs/database/src/seeder/`)를 node 로 불러 만드는 함수를 그대로 부른다(scripts/db-schema.mjs:16 과 같은 방식). `SEED_SAMPLE_DATA=1` 은 그 점검 프로세스 안에서만 켠다.
