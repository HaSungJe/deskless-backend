# 테스트 데이터(샘플 시드)

개발 · 테스트 DB 에 업체 71곳(서울 10 · 전국 61) · 객실 · 계정 · 문의를 넣는다 — 프론트 화면 개발 · 스토리 테스트용. **운영 DB 에서는 켜지 않는다.**

## 켜기

1. `.env`
   - `SEED_SAMPLE_DATA=1`
   - `GATEWAY_PUBLIC_URL=<게이트웨이 공개 주소>` — 로컬 실행은 `http://localhost:<GATEWAY_PORT>`, 쿠버네티스는 게이트웨이 Ingress 의 공개 주소. 사진 주소가 `<이 주소>/sample/<파일>.png` 가 된다
2. 마이그레이션이 적용된 DB 로 user-service 를 다시 띄운다(부팅 시드). admin-service · gateway 도 다시 띄운다(사진 주소 · `/sample/` 경로)
3. user-service 로그에 `t_store: 기본 데이터 71건 입력 (…)` 같은 줄이 찍힌다. 다시 띄워도 늘지 않는다 — 고정 ID 라 이미 있는 행은 건너뛰고, 업체 관리자가 바꾼 값도 덮지 않는다. 서울 10곳만 들어가 있던 개발 DB 는 다시 띄우면 전국 61곳만 더 들어간다(`61건 입력`)

끄기: `SEED_SAMPLE_DATA=0`(또는 비움) — 이미 들어간 행은 그대로 남는다. 지우는 기능은 없다(개발 DB 를 새로 만든다).

## 계정

- **총관리자** — 기본 시드 `admin` / `1234`(첫 로그인 때 변경)
- **업체 총관리자** — 업체마다 1명, 아이디 `manager` · 비밀번호 `1234`(비밀번호 변경 요구 없음). 업체코드 + 아이디로 로그인 — `POST /api/v1/admin-service/manager/login`, 프론트 주소 `/manager/<업체코드>/login`

| # | 업체 | 업체코드 |
|---|---|---|
| 01 | 바로방 강남역점 | `5a3e0200000000000000000000000001` |
| 02 | 바로방 홍대입구점 | `5a3e0200000000000000000000000002` |
| 03 | 바로방 잠실점 | `5a3e0200000000000000000000000003` |
| 04 | 바로방 성수점 | `5a3e0200000000000000000000000004` |
| 05 | 바로방 여의도점 | `5a3e0200000000000000000000000005` |
| 06 | 바로방 종로점 | `5a3e0200000000000000000000000006` |
| 07 | 바로방 신촌점 | `5a3e0200000000000000000000000007` |
| 08 | 바로방 건대입구점 | `5a3e0200000000000000000000000008` |
| 09 | 바로방 이태원점 | `5a3e0200000000000000000000000009` |
| 10 | 바로방 합정점 | `5a3e0200000000000000000000000010` |

- 전국 11 ~ 71 의 업체코드도 같은 규칙 — `5a3e02` + 번호 26자리(예: 44 바로방 온양온천점 `5a3e0200000000000000000000000044`). 업체 총관리자도 업체마다 `manager` / `1234`

- **이용자** — `sns_id` `KAKAO` · `sns_user_id` `sample-user-01`, 닉네임 `테스트 이용자`, 휴대폰 인증 완료. 이용자는 SNS 로만 로그인하므로 카카오 로그인 창으로는 이 계정에 들어갈 수 없다 — `POST /api/v1/user-service/user/login` 에 `{"sns_id": "KAKAO", "sns_user_id": "sample-user-01"}` 를 바로 보낸다(프론트의 개발용 테스트 로그인)

## 문의

샘플 이용자가 쓴 문의 71건(고정 ID `5a3e17…`) — 상태 · 카테고리 거르기, 페이지 넘김, 답변 · 블라인드 · 해제를 바로 시험할 수 있다. 값은 [sample-seed.data.ts](../../libs/database/src/seeder/sample-seed.data.ts) 의 `SAMPLE_INQUIRY_TEMPLATES`(일반 13개 — 카테고리 7개 모두) · `SAMPLE_INQUIRY_SPAMS`(광고 2개) · `SAMPLE_INQUIRY_COUNTS`(대상별 개수).

| 대상 | 건수 | 상태 |
|---|---|---|
| 업체 01 바로방 강남역점 | 22 | 접수 10 · 답변완료 10 · 블라인드 2 — 한 페이지(20건)를 넘는다 |
| 업체 02 바로방 홍대입구점 | 3 | 접수 1 · 답변완료 1 · 블라인드 1 |
| 업체 03 ~ 10 | 3건씩 | 접수 2 · 답변완료 1 |
| 바로방(업체 없음) | 22 | 접수 10 · 답변완료 10 · 블라인드 2 — 한 페이지를 넘는다 |

- 이용자의 내 문의 목록에는 71건이 다 나온다(샘플 이용자로 로그인).
- 일반 문의는 본보기를 대상마다 밀어 가며 돌려 써서 카테고리가 고르게 섞이고, 번갈아 접수 · 답변완료다. 스팸(광고)은 블라인드다.
- 답변 · 블라인드 계정은 업체 문의면 그 업체의 업체 총관리자(`manager`), 바로방 문의면 기본 시드의 총관리자(`admin`) — `admin` 이 없으면(아이디를 바꿨으면) 바로방 문의는 모두 접수로 들어간다.
- 등록일은 넣는 때부터 몇 시간 ~ 9일 전으로 흩어 넣는다(최신순 목록 · 날짜 표시를 볼 수 있게). 답변은 등록 3시간 뒤, 블라인드는 1시간 뒤.
- 문의 카테고리 7개 · 상태 3개는 테스트 데이터가 아니라 **기본 데이터 시드**다(`SEED_SAMPLE_DATA` 와 상관없이 user-service 가 부팅할 때 넣는다 — [seeder.targets.ts](../../libs/database/src/seeder/seeder.targets.ts) `INQUIRY_CATEGORY_SEED_DATA` · `INQUIRY_STATE_SEED_DATA`).

## 사진

- 저장 키 `sample/<파일>.png` — S3 에 없다. 게이트웨이가 [apps/gateway/src/assets/sample/](../../apps/gateway/src/assets/sample/) 을 `/sample/` 경로로 내주고(빌드 때 nest-cli `assets` 가 dist 로 복사), 저장소 어댑터가 공개 주소를 `GATEWAY_PUBLIC_URL/sample/<파일>.png` 로 만든다. API 응답의 사진 주소가 그대로 이 주소다
- 업체 관리자가 샘플 사진을 지우면 행만 소프트 삭제되고 파일은 남는다(저장소를 부르지 않는다). 새로 올리는 사진은 S3(presigned URL) — `AWS_S3_BUCKET` 이 비어 있으면 게이트웨이 내부 파일 저장소(`/files/<키>` — [aws-setup.md](aws-setup.md) "AWS 없이 돌리기")
- 파일: 업체 `store-<NN>-<1|2>.png`(낮 · 밤 외관), 그룹 `room-<NN>-<그룹>-<1|2>.png`(침대 쪽 · TV · 책상 쪽), 왼쪽 아래 라벨(`STORE 01` · `ROOM 01-2`)
- 모두 450장(업체 142 · 그룹 308). 다시 그리기: `npm run sample:images`([scripts/sample-images.mjs](../../scripts/sample-images.mjs) — 외부 패키지 없음). 업체 · 그룹 수를 바꾸면 스크립트의 `GROUP_COUNTS` 와 `SAMPLE_STORES` 를 같이 고친다(서울 01 ~ 10 사진은 다시 그려도 그대로)
